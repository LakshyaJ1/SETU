# Compiled offline road graphs

## Purpose

The Delhi/NCR JSON contains 3,185,592 nodes and 7,255,057 directed edges. Parsing
that document and materializing arrays for each app process delayed the first
route and consumed substantial Java heap. The compiler preserves those nodes,
edges, directions and names in a read-only, memory-mappable representation.
The portable map contract is unchanged; this is an internal compiled artifact,
not completion of the production routing/curvature/anchor database.

## Format: setu.road-graph.v1

All numeric fields are little-endian. The decompressed file begins with the eight
ASCII bytes `SETUGR1\n`, followed by three signed int32 counts: nodes, directed
edges and unique road names. The body consists of contiguous arrays in this order:

| Array | Type | Count |
| --- | --- | --- |
| Latitude | float64, degrees | nodes |
| Longitude | float64, degrees | nodes |
| First outgoing edge | int32 | nodes |
| Source node | int32 | edges |
| Target node | int32 | edges |
| Next outgoing edge | int32 | edges |
| Segment length | float64, metres | edges |
| Road-name index | int32 | edges |

Adjacency uses `-1` for termination. Links must point to a lower edge index;
every edge must belong to its source node's chain exactly once. Node and name
references are zero-based. The arrays are followed by each UTF-8 road name as an
int32 byte length and payload, with no trailing bytes. Coordinates, lengths,
counts, links, UTF-8 and references are validated before a graph is returned.
Limits: 4 million nodes, 8 million edges, 1.2 million names, 200 UTF-16 code units
per name and 384 MiB decompressed graph. Memory mapping does not eliminate the
physical memory needed to read pages, or the per-route search working arrays.

`graph.json` records schema, archive name, compressed/decompressed bytes and
SHA-256 hashes, source JSON SHA-256, and graph counts. Bundling requires matching
source and archive hashes. Runtime reuse requires the source checksum to match
the region; arbitrary imported binary files are not accepted. Extraction is
atomic and cancellable. Every open checks the decompressed checksum and graph
structure; cache corruption triggers re-extraction of the packaged archive.

## Reproduction

```powershell
python -m tools.build_road_graph data/interim/delhi-ncr-region-v4/roads.json data/interim/new-compiled-graph
python -m tools.build_map_pack data/interim/delhi-ncr-region-v4 dist/maps/new-ncr.setumap --android-assets android/app/src/main/assets/regions/delhi --vector-tiles data/interim/delhi-ncr-tiles-v2 --compiled-graph data/interim/new-compiled-graph
```

Both generators refuse to overwrite their new output destinations. Android
bundled assets are intentionally regenerated by `--android-assets`. The compiler
streams road records with bounded record sizes and standard-library arrays; it
does not load the full source JSON document or require a new Android dependency.
The full compiled graph is 237,950,972 bytes, archived to 104,381,337 bytes; the
larger archive trades APK size for eliminating per-process JSON parsing. The
source topology and Delhi/NCR map envelope do not change.

## Verification scope

Python checks deterministic archives, source hashes, adjacency and SI lengths,
bounded parsing and malformed records. JVM tests cover mapped read-only buffers,
corrupt headers/arrays/names, cancellation, segment snapping and connected-road
alternatives without invented road links. Android checks compare a Python-compiled
fixture with the JSON reader, route all included Bengaluru destinations, and
measure full NCR cold/warm loading and corrupt-cache recovery.

The checked APK, exact hashes, test logs and measured emulator timings are in
`verification/android/compiled-routing/README.md`. The final package was regenerated
without the previous incremental APK container: all 219 archive entries matched
the initially tested package byte-for-byte, while 56,224,480 bytes of obsolete ZIP
space were removed. The compact package was installed and tested again.

These checks establish file/runtime behavior, not production driving safety or
GPS-free navigation. Turn restrictions, live closures, complete access rules,
spatial indexing and full-estimator map matching remain production work.
